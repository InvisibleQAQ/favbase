# app/hooks

app.html 专用共享 hooks（跨 section 复用；平台无关）。与 `lib/hooks/`（跨 context 共享，如 useSettings）区分：本目录的 hook 只跑在 Extension Page context。

## 模块结构

- `background-jobs-store.ts` — 模块级 `useSyncExternalStore` job store **兼 Pipeline Run scheduler**（audit 2026-08-17 #7 收敛产物），跨 Hash Router 挂载保留 `sync|extract|embed|tag|transcribe` 未完成态。`startJob(platform, kind, runner, collision='drop')` 的碰撞语义是**显式策略**：`'drop'`（active 时拒绝，`started:false`——sync/extract 跨挂载去重）、`'queue'`（FIFO 入 pending，active settle 成功**或失败**后由 store 同步出队接续）、`'coalesce'`（并入最新的**同为 coalesce 派发**的 pending run，本次 runner 丢弃；绝不并入 `'queue'` 条目——可互换性由派发方声明，如全量 backlog embed drain 互吸、但不吸 streaming drain）。句柄 `{started, dispatch:'started'|'queued'|'coalesced'|'dropped', settled}`，settled 结算于**本次派发对应的 run**。调用方禁止再用 settled-promise 重试循环自造排队。owner token 保证旧 run 迟到 settlement/progress 不覆盖新 run；`trackJobRun` 仅为不可控旧 Promise 的兼容 observer（group settle 后同样 drain pending——`bilibili:transcribe` key 上 observer 与 owner 混用），不得用于需要暂停的 pipeline。**闸门经 `setJobGate(reader)` 依赖注入**（本模块属泛型层，禁止直接 import `library-gate`），且在 run **实际启动时**评估（含 pending 出队时刻）：命中时 job 照常创建、runner 照常启动，只是 control born-paused、初始 phase `'paused'`，`started` 仍为 `true`——**绝不能返回 `{started:false}`**，否则排队中的工作被结算成空。仅注册 reader 不触碰已运行 run（暂停靠 `library-gate` 的 `pauseJob` fan-out）。reader 抛错被吞（记 `console.error`）并按未暂停处理。
- `pipeline-run-control.ts` — 单 run cooperative pause 状态机；Pause 先进入 `pausing`，worker 在下一个 `checkpoint()` 才进入 `paused`，Resume 从 `pausing|paused` 都回到 `running`：前者撤销尚未生效的暂停意图，后者释放等待，禁止丢失 checkpoint 前到达的 resume。不取消当前请求或 DB 写入。**`createPipelineRunControl(onPhaseChange, initialPhase='running')` 支持 born-paused**（闸门用）：初始 `'paused'` 的 run 在**第一个** `checkpoint()` 就挂起，因此 checkpoint 守卫是 `if (phase === 'running') return`；resume 若早于首个 checkpoint，checkpoint 直接放行、不产生第二个 worker。
- `collection-processing-jobs.ts` — 六平台 Embed/Tags 的 app-runtime 执行器。每个 `(jobPlatform,lane)` 各自串行、各自可暂停，不同平台 Embed lane 可并行；item 在领取前 checkpoint。碰撞排队**全部由 job store 的策略执行**，本模块只声明：tag batch = `'queue'`（每批 ids 不同，逐批必跑）、embed batch = `'coalesce'`（runner 都是全量 `'chunked'` backlog drain，可互换，N 个碰撞收敛为 1 个 pending drain）、streaming drain = `'queue'`（排在同 lane batch run 之后）；均不丢工作，模块内无 settled 重试递归。streaming item 进入模块级 inbox（item 队列 + done/total 是 lane 的 item 级簿记，留在本模块），drain settle 后若 inbox 有迟到 item 则 re-wake。同步收尾时 Embed 恒派发平台 `'chunked'` backlog，Tags 仍只吃本轮 ids；provider 保存恢复则只派发对应平台 Embed/Tags backlog。诊断：`scheduler:batch-queued`/`batch-coalesced`/`stream-queued` 取代旧 collision/retry 事件；终态 `job:completed|failed` trace 在 runner wrapper 内发出（queued run 的 settled 解析时 store 可能已启动下一个 run，读快照会串台）。队列仅存活于当前 app.html，不伪装持久恢复。
- `collection-job-platform.ts` — 纯平台判别符 ↔ background-job namespace 映射；exhaustive `Record<CollectionPlatform,string>` 是需要通用正反翻译时的唯一事实源，供 `library-gate` 与 provider 恢复门面共同消费。禁止在这里读 storage 或注册 job gate，避免纯翻译触发 app-runtime 副作用。
- `collection-processing-resume.ts` — provider 保存后的平台感知恢复门面：`resumeCollectionProcessing(platform,'embedding'|'llm')` 经纯 mapping Module 派发一个 Embed/Tags backlog run。Settings 不接触 job key、查询或 lane collision；active lane 的后续跑仍由 `startBatchLane` 保证。
- `use-collection-library.ts` — 单列表 + facet + 手动同步的共享状态机；同步经 `startJob(logTag,'sync')`，把 cooperative checkpoint 传给平台 `syncFn`，并暴露同 namespace 的 typed `syncJob`/`embedJob`/`tagJob` 给 pipeline Adapter。平台只注入稳定的 query/facets/lastSynced/sync/error-classifier Interface。`controlledFilter?: string | null` 是唯一的受控 seam（docs/20 中-6）：`undefined` = 非受控（`setFilter` 拥有 filter，五个远程平台现状）；给值（`null` = 无筛选）即外部事实源（如路由参数）拥有——hook 读它、变化时在 **render 期**把 page 回 1（非 effect，避免一次「新 filter + 旧 page」废查询）、`setFilter` 变 no-op，杜绝两个事实源。**触发时机（按钮/挂载/daily）是 adapter 的策略，hook 不带 auto-on-mount 开关**。单测 `use-collection-library.test.tsx`（受控/非受控 filter 归属与回页）。
- `collection-phase.ts` — `resolveCollectionPhase(state): CollectionPhase`（audit docs/15 HIGH-2 的收敛产物）：收藏页内容区的 8 分支优先级阶梯纯函数。返回 discriminated union `'tag-filtered' | 'query-error' | 'auth-failed' | 'sync-error' | 'skeleton' | 'empty-library' | 'no-matches' | 'grid'`。**分支顺序即契约**——顺序封在这一处，各 view 只做 `switch(phase)` → 平台节点映射，view 不再各自维持顺序（消除「某平台漏 authFailed 短路」类静默 bug）。入参是布尔旗标对象（tagFiltered/queryError/authFailed/syncErrorEmpty/metaLoading/syncingEmpty/libraryEmpty/loading/noMatches）；无 authFailed 概念的平台（github：token 缺失走 NoTokenState 整页短路）传 `authFailed:false`。`collection-phase.test.ts` 逐分支 + 全旗标叠加锁死顺序
- `use-processing-coverage.ts` — 平台级 DB Processing Coverage hook：返回 `loading|ready|error` 判别状态，订阅 durable content/embedding/tagging 事件，并以 100ms trailing window 合并聚合查询；无轮询。
- `pipeline-segments.ts` — 纯 Adapter Module：平台声明 stage→coverage key 与可选 runtime；`backgroundJobRuntime(job, progressAdapter?)` 输出**纯展示** runtime 快照（phase/progress/lastProgress/error，无 pause/resume——段级控件已下线，运行控制归 per-platform 闸门 `library-gate.ts` + `components/library-gate/`），`completedProgress:'last-run'` 只给 Fetch 保留本次总数并显示 100%。Module 统一 live-over-idle、unknown、loading/error 与 job payload 校验。
- `daily-sync-gate.ts` — 每日自动同步闸门纯函数（无 React/storage，单测 `daily-sync-gate.test.ts`）：`isSameLocalDay(a,b)`（本地年月日三相等）、`shouldAutoSync(lastSyncedAt, now)`（`null`→true，否则「非今天」→true）。**唯一数据源 = `sources.lastFetchedAt`**（经 `getPlatformLastSyncedAt` 读，**不建表不加 storage**）；手动同步也刷 `lastFetchedAt`，故当天手动拉过即视为「今天已同步」自动路径跳过。
- `library-gate.ts` — per-platform「知识库构建」持久闸门门面（**平台感知层**，与 `use-daily-auto-sync.ts` 同档：读 storage + 认识平台词汇；泛型层不得 import 它）。持久值 = `libraryGateStorage`（`local:library-gate`）里**暂停中的平台列表**，`[]` = 全部运行（第 7 个平台接入零改动）。模块级 `Set<CollectionPlatform>` 同步镜像供非 React 的 `startJob` 当 tick 判定，模块加载时 `getValue()` 填充 + `.watch()` 订阅跨 context 变更（形态同 `lib/i18n/index.ts` 的 `currentMessages`）。导出 `isLibraryPaused(jobPlatform)` / `gatePlatformOf(jobPlatform)` / `pauseLibrary` / `resumeLibrary` / `useLibraryGate(platform)`；正反 namespace 翻译委托给无副作用的 `collection-job-platform.ts`。`pause/resumeLibrary` 先改镜像（同 tick 生效，防点击与派发竞态）→ 再写 storage（watch 回声因值相同被吞）。**运行中 run 的 `pauseJob`/`resumeJob` 联动（5 个 kind fan-out）在 `applyPaused` 内按新旧集合 diff 驱动**——点击路径与跨 context watch（另一个 app.html tab 的写入）共用同一处联动逻辑；pause/resume 相位守卫使无 run 时（如模块加载的初始读）为幂等 no-op。**模块加载时 `setJobGate(isLibraryPaused)` 自注册**，app.html 的加载保证来自 `use-daily-auto-sync` 的 import（它由 `App.tsx` 挂载）。
- `use-jobs-badge.ts` — 工具栏 badge 同步 hook（挂 DashboardLayout，泛型层；单测 `use-jobs-badge.test.ts`）：`useRunningJobs().length` → `browser.action.setBadgeText`（数字，0 清空）+ `setTitle`（复用 `backgroundJobs.reminder` 文案当悬停提示，locale 切换随 re-render 更新）+ warning 橙底色。**只写不清理**：badge 文本是浏览器会话级持久，关掉 app.html 后由 SW 清道夫兜底擦除（`lib/background/jobs-badge.ts`），页面侧不做 unload 清理（unload 不可靠）。action API 失败一律吞掉只 warn（badge 属锦上添花，不能拖垮页面）。
- `use-daily-auto-sync.ts` — 每日首开自动同步协调器 hook（挂 `App.tsx`，跨路由常驻，单测 `use-daily-auto-sync.test.tsx`）。`useDailyAutoSync(platforms, deps?)` 的 `platforms` **必填**，由 `App.tsx` 注入 app 根 `collection-platform-auto-sync.ts` 的 `AUTO_SYNC_PLATFORMS`——hook 无默认 registry，本目录对 `sections/` 零 import（契约守卫，docs/20 高-3）。本文件拥有类型 `AutoSyncPolicy`（`probeReady` + 可选 `isSilentError`，各平台在 adapter 文件旁声明为 `<p>AutoSyncPolicy`）/ `AutoSyncDefinition`（+ `runSync`）/ `AutoSyncPlatform`（+ `itemPlatform`/`jobPlatform`，后者由 registry 经 `jobPlatformForCollection` 派生）。**触发 = mount + `visibilitychange`(visible)**（天然覆盖「登录后切回 tab 补拉」）；**节流 `EVALUATE_THROTTLE_MS=30_000`**（ref 记 `lastEvalAt`，用注入的 `deps.now()` 以便测试，防频繁切 tab 的 DB 查询风暴）。evaluate 每平台 `Promise.all` 并行 + try/catch 隔离（单平台失败/probe 抛错只 `console.error`，不阻断其它）：`shouldAutoSync` 未命中或 `probeReady` false → 跳过；否则 `deps.startJob(jobPlatform,'sync', runner)` 派发（跨路由存活 + 并发去重 + indicator 可见），runner 只跑共享 Sync Adapter（`runSync`，处理派发已内含）+ `isSilentError` 命中的错不 rethrow。`deps` 可注入（`initDb`/`now`/`getLastSynced`/`isPaused`/`startJob`）。**闸门插桩在 `shouldAutoSync` 之后、`probeReady` 之前**（`deps.isPaused(jobPlatform)`，默认 `isLibraryPaused`）：暂停中不发探针请求、不刷 `sources.lastFetchedAt`，解除暂停后当天仍会补跑；这只是省掉噪音 job，真正的兜底是 `startJob` 的 born-paused。**StrictMode double-invoke 由闸门 + startJob 去重 + 节流天然幂等**。

## 约定

- **config 函数必须引用稳定**（模块级常量或 useCallback）——它们在 effect 依赖数组里，不稳定引用会每 render 重查。
- **泛型层零 storage / 零平台导入**：唯一依赖 `@/lib/database` 的 `initDbProxy`。auth/配置解析（如 X 的 `getXAuth()`）必须留在各平台的共享 Sync Adapter 模块（`sections/<platform>/<platform>-sync-adapter.ts`）内，hook 的 `syncFn` 只引用 adapter。**这条约束的是模块不是目录**：本目录分两档——泛型层（`background-jobs-store` / `pipeline-run-control` / `collection-processing-jobs` / `use-collection-library` / `collection-phase` / `daily-sync-gate` / `pipeline-segments` / `use-processing-coverage`）与平台感知层（`library-gate` / `use-daily-auto-sync`，读 storage + 认识平台词汇是合法的）。跨档只能**由平台感知层向泛型层注入**（`setJobGate` / `deps`），泛型层反向 import 即视为掉档。**两档都不得 import `sections/`**：六平台 Sync Adapter 的聚合点在 app 根 `collection-platform-auto-sync.ts`，经 `App.tsx` 注入进 `useDailyAutoSync(platforms)`；契约测试扫描本目录全部非测试模块守卫。
- **平台同步语义单一实现**（audit #6 铁律）：「平台同步成功意味着什么」只在各 section 的 `*-sync-adapter.ts` 定义一次；手动 hook 与 app 根 daily registry（`collection-platform-auto-sync.ts`）都引用同一函数，禁止在任一触发方复制认证解析或后处理派发。触发策略留触发方：UI 门/冷却在页面 hook；daily 的 readiness/静默错误以 `<p>AutoSyncPolicy` 在 adapter 文件旁声明（不进 `run<P>Sync`），由 registry 配对。
- 消费方（薄 adapter）：`sections/github-stars/use-github-stars.ts`（useSettings token UI 门）、`sections/x/use-x-bookmarks.ts`（`xLastSyncStorage` 订阅 + 冷却）、`sections/zhihu/use-zhihu-favorites.ts`、`sections/youtube/use-youtube-playlists.ts`（useSettings 凭据门（github 模式）：apiKey+channel 同步读 `hasConfig`，无异步授权探针——API key 形态单维度）、`sections/bookmarks/use-bookmarks.ts`（路由 folderId 经 `controlledFilter: folderId ?? null` 受控注入 + adapter 内 `useEffect` 挂载 `sync()`，docs/20 中-6）。**不适用**：bilibili（folders+videos 双 hook）——形态不同，不强行塞进该抽象（docs/15 HIGH-1 范围圈定），但其 sync runner 同样只调共享 Sync Adapter。
