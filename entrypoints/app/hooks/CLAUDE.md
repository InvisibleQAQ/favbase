# app/hooks

app.html 专用共享 hooks（跨 section 复用；平台无关）。与 `lib/hooks/`（跨 context 共享，如 useSettings）区分：本目录的 hook 只跑在 Extension Page context。

## 模块结构

- `background-jobs-store.ts` — **模块级单例** store（原型即 `sections/bookmarks/use-bookmark-extraction.ts` 的模式：裸模块 `Map<`${platform}:${kind}`,Job>` + listener `Set` + `useSyncExternalStore`），承载所有平台长任务（`kind: 'sync'|'embed'|'tag'|'transcribe'`）的运行态。`Job { platform, kind, running, progress:unknown, error:unknown, generation }`。**为何模块级**：app.html 是 Hash Router，切走 section 只卸载组件、页面 JS context 不销毁——把 job 态放这里，切走再回来 re-subscribe 同一个在飞 job（进度重连），且 `startJob` 的 `if(running)return` **跨挂载去重**（组件本地守卫做不到，这正是原 zhihu 二次 sync bug 的根因）。`startJob(platform,kind,runner)`：runner 收 `setProgress` sink，成功 `generation++`、抛错存 `error`（消费方 classify），fire-and-forget 无 AbortSignal。选择器：`useJob(platform,kind)`（单 job 快照，getSnapshot 返回稳定引用）、`useRunningJobCount()`（驱动全局 header 提醒，返回 primitive 天然稳定）。纯读 `getJob`/`getRunningJobCount` 供单测（`background-jobs-store.test.ts` 用互异 platform key 避免模块态串扰，测去重/generation/progress/error/稳定引用）。**ST4：bookmarks 正文提取也跑进本 store 成 `bookmarks:sync` job**（原 bespoke 提取单例并入，见 `sections/bookmarks/use-bookmark-extraction.ts`）——全局勿关页计数含 bookmarks；但 bookmarks 的 embed/tag **逐条 `void` 不入 store**（`onItemExtracted` orphan-safety + done/total 分母 run 前不可知），区别于 ST3 里 4 平台 x/github/zhihu/youtube 的批量 `embed`/`tag` job。**ST5：store 现也承载 `bilibili:transcribe`**（手动单视频转录运行态，progress 恒 null indeterminate——只反映运行态供全局计数）。经 `sections/bilibili/use-video-transcribe.ts` 注入 `TranscriptionCoordinator` 的 `trackRun` 回调，把 `transcribeAndPersist` promise 包成 job（lib 层 coordinator 不 import 本 store，分层守住）；promise floating（dispose 不取消）故切路由转录仍计入全局提醒。activeBvid 串行保证同时只有一个 `bilibili:transcribe` job（与 startJob 单 key 去重一致）。auto-transcribe 不入 store（app.html 编排、卸载即停）
- `use-collection-library.ts` — `useCollectionLibrary<TItem, TFacet, TProgress, TError>`：「单列表 + facet chips + 手动同步」收藏页的平台无关状态机（audit docs/15 HIGH-1 的收敛产物）。持有全部编排逻辑：搜索 300ms 防抖（`searchRef` 值比对，真变化才重置 page=1）、分页查询 effect（`cancelled` 旗标 + `initDbProxy()` 幂等 join + queryVersion 重查）、库元信息 `refreshMeta`（`Promise.all` facets/lastSynced/无筛选 total + `mountedRef` 守卫）、**sync 态派生自 `background-jobs-store` 的 `useJob(logTag,'sync')`**（不再组件本地 useState）：`syncing=job.running`、`syncProgress=job.progress as TProgress`、`syncError=useMemo(classifyError(job.error))`；`sync()` = `startJob(logTag,'sync', …syncFn)`（去重下沉单例）；**完成信号 = generation**：`lastSyncGenRef` 挂载时 adopt 当前值（fresh mount 靠自身初始 meta/query 载入最新数据），后续 generation 增长（离开期间完成的 sync）触发 `refreshMeta`+`queryVersion++`。**ST3：暴露 `embedJob`/`tagJob = useJob(logTag,'embed'/'tag')`（`BackgroundJob|null`）**——平台无关扩展（无平台分支，守 state-management spec），供各 view 渲染 embed/tag done/total 进度 caption；其运行态自动计入全局勿关页计数（`useRunningJobCount`），**但完成 generation 有意不接 `refreshMeta`/`queryVersion`**（embed 只改 content_state 不增行；tag 刷新已由 `item-tagged` 领域事件驱动），区别于 sync 的完成信号。`totalPages = max(1, ceil(total/pageSize))`（默认 pageSize=24）。平台注入点 5 个：`queryFn`（吃归一化 `CollectionQueryParams { filter, search, page, pageSize }`）、`facetsFn`、`lastSyncedFn`、`syncFn`、`classifyError`（+`logTag` console 前缀）。返回泛化字段名（items/filter/setFilter/facets/...），平台 adapter 负责映射回领域命名
- `collection-phase.ts` — `resolveCollectionPhase(state): CollectionPhase`（audit docs/15 HIGH-2 的收敛产物）：收藏页内容区的 8 分支优先级阶梯纯函数。返回 discriminated union `'tag-filtered' | 'query-error' | 'auth-failed' | 'sync-error' | 'skeleton' | 'empty-library' | 'no-matches' | 'grid'`。**分支顺序即契约**——顺序封在这一处，各 view 只做 `switch(phase)` → 平台节点映射，view 不再各自维持顺序（消除「某平台漏 authFailed 短路」类静默 bug）。入参是布尔旗标对象（tagFiltered/queryError/authFailed/syncErrorEmpty/metaLoading/syncingEmpty/libraryEmpty/loading/noMatches）；无 authFailed 概念的平台（github：token 缺失走 NoTokenState 整页短路）传 `authFailed:false`。`collection-phase.test.ts` 逐分支 + 全旗标叠加锁死顺序

## 约定

- **config 函数必须引用稳定**（模块级常量或 useCallback）——它们在 effect 依赖数组里，不稳定引用会每 render 重查。
- **泛型层零 storage / 零平台导入**：唯一依赖 `@/lib/database` 的 `initDbProxy`。auth 解析（如 X 的 `getXAuth()`）必须留在各平台 adapter 的 `syncFn` 闭包内。
- 消费方（薄 adapter）：`sections/github-stars/use-github-stars.ts`（useSettings token 门 + estimatedTotal 进度计算）、`sections/x/use-x-bookmarks.ts`、`sections/zhihu/use-zhihu-favorites.ts`、`sections/youtube/use-youtube-playlists.ts`（useSettings 凭据门（github 模式）：apiKey+channel 同步读 `hasConfig`，无异步授权探针——API key 形态单维度）。**不适用**：bookmarks（auto-on-mount 同步）、bilibili（folders+videos 双 hook）——形态不同，不强行塞进该抽象（docs/15 HIGH-1 范围圈定）。
