# app/hooks

app.html 专用共享 hooks（跨 section 复用；平台无关）。与 `lib/hooks/`（跨 context 共享，如 useSettings）区分：本目录的 hook 只跑在 Extension Page context。

## 模块结构

- `background-jobs-store.ts` — 模块级 `useSyncExternalStore` job store，跨 Hash Router 挂载保留 `sync|extract|embed|tag|transcribe` 未完成态。`startJob` 持有 owner token、cooperative control、`running|pausing|paused|completed|failed` phase、末次成功 `lastProgress` 与 `{started,settled}` 句柄；同 key 去重且旧 run 的迟到 settlement 不能覆盖新 run。`trackJobRun` 仅为不可控旧 Promise 的兼容 observer，不得用于需要暂停的 pipeline。**闸门经 `setJobGate(reader)` 依赖注入**（本模块属泛型层，禁止直接 import `library-gate`）：闸门命中时 job **照常创建、runner 照常启动**，只是 control born-paused、job 初始 phase 为 `'paused'`，`started` 仍为 `true`——**绝不能返回 `{started:false}`**，否则 `collection-processing-jobs` 的 `startBatchLane`/`wakeLane` 会在已 resolve 的 settlement 上无限递归重试。reader 抛错被吞（记 `console.error`）并按未暂停处理。
- `pipeline-run-control.ts` — 单 run cooperative pause 状态机；Pause 先进入 `pausing`，worker 在下一个 `checkpoint()` 才进入 `paused`，Resume 从 `pausing|paused` 都回到 `running`：前者撤销尚未生效的暂停意图，后者释放等待，禁止丢失 checkpoint 前到达的 resume。不取消当前请求或 DB 写入。**`createPipelineRunControl(onPhaseChange, initialPhase='running')` 支持 born-paused**（闸门用）：初始 `'paused'` 的 run 在**第一个** `checkpoint()` 就挂起，因此 checkpoint 守卫是 `if (phase === 'running') return`；resume 若早于首个 checkpoint，checkpoint 直接放行、不产生第二个 worker。
- `collection-processing-jobs.ts` — 六平台 Embed/Tags 的 app-runtime 执行器。每个 `(jobPlatform,lane)` 各自串行、各自可暂停，不同平台 Embed lane 可并行；item 在领取前 checkpoint。后到 batch 等当前同 lane settlement 后接续，streaming item 进入模块级 inbox，均不得把去重变成丢工作。同步收尾时 Embed 恒派发平台 `'chunked'` backlog，Tags 仍只吃本轮 ids；provider 保存恢复则只派发对应平台 Embed/Tags backlog。队列仅存活于当前 app.html，不伪装持久恢复。
- `collection-job-platform.ts` — 纯平台判别符 ↔ background-job namespace 映射；exhaustive `Record<CollectionPlatform,string>` 是需要通用正反翻译时的唯一事实源，供 `library-gate` 与 provider 恢复门面共同消费。禁止在这里读 storage 或注册 job gate，避免纯翻译触发 app-runtime 副作用。
- `collection-processing-resume.ts` — provider 保存后的平台感知恢复门面：`resumeCollectionProcessing(platform,'embedding'|'llm')` 经纯 mapping Module 派发一个 Embed/Tags backlog run。Settings 不接触 job key、查询或 lane collision；active lane 的后续跑仍由 `startBatchLane` 保证。
- `use-collection-library.ts` — 单列表 + facet + 手动同步的共享状态机；同步经 `startJob(logTag,'sync')`，把 cooperative checkpoint 传给平台 `syncFn`，并暴露同 namespace 的 typed `syncJob`/`embedJob`/`tagJob` 给 pipeline Adapter。平台只注入稳定的 query/facets/lastSynced/sync/error-classifier Interface。
- `collection-phase.ts` — `resolveCollectionPhase(state): CollectionPhase`（audit docs/15 HIGH-2 的收敛产物）：收藏页内容区的 8 分支优先级阶梯纯函数。返回 discriminated union `'tag-filtered' | 'query-error' | 'auth-failed' | 'sync-error' | 'skeleton' | 'empty-library' | 'no-matches' | 'grid'`。**分支顺序即契约**——顺序封在这一处，各 view 只做 `switch(phase)` → 平台节点映射，view 不再各自维持顺序（消除「某平台漏 authFailed 短路」类静默 bug）。入参是布尔旗标对象（tagFiltered/queryError/authFailed/syncErrorEmpty/metaLoading/syncingEmpty/libraryEmpty/loading/noMatches）；无 authFailed 概念的平台（github：token 缺失走 NoTokenState 整页短路）传 `authFailed:false`。`collection-phase.test.ts` 逐分支 + 全旗标叠加锁死顺序
- `use-processing-coverage.ts` — 平台级 DB Processing Coverage hook：返回 `loading|ready|error` 判别状态，订阅 durable content/embedding/tagging 事件，并以 100ms trailing window 合并聚合查询；无轮询。
- `pipeline-segments.ts` — 纯 Adapter Module：平台声明 stage→coverage key 与可选 runtime；`backgroundJobRuntime(job, progressAdapter?)` 输出**纯展示** runtime 快照（phase/progress/lastProgress/error，无 pause/resume——段级控件已下线，运行控制归 per-platform 闸门 `library-gate.ts` + `components/library-gate/`），`completedProgress:'last-run'` 只给 Fetch 保留本次总数并显示 100%。Module 统一 live-over-idle、unknown、loading/error 与 job payload 校验。
- `daily-sync-gate.ts` — 每日自动同步闸门纯函数（无 React/storage，单测 `daily-sync-gate.test.ts`）：`isSameLocalDay(a,b)`（本地年月日三相等）、`shouldAutoSync(lastSyncedAt, now)`（`null`→true，否则「非今天」→true）。**唯一数据源 = `sources.lastFetchedAt`**（经 `getPlatformLastSyncedAt` 读，**不建表不加 storage**）；手动同步也刷 `lastFetchedAt`，故当天手动拉过即视为「今天已同步」自动路径跳过。
- `auto-sync-registry.ts` — 六平台自动同步契约。Bilibili `runSync` 先拉 folders，再动态 import `runBiliStreamingSync`，按 API 自然 Source 顺序运行同一 Fetch→durable item→Transcript runtime；不做 pending scan 或第二次排序，仍返回 `[]`（Embed/Tag 由逐条转录 enqueue）。Bookmarks 继续链 `startBookmarkExtraction()`。动态 import 保持重 worker 不进入 App 启动 chunk
- `library-gate.ts` — per-platform「知识库构建」持久闸门门面（**平台感知层**，与 `auto-sync-registry.ts` 同档：读 storage + 认识平台词汇；泛型层不得 import 它）。持久值 = `libraryGateStorage`（`local:library-gate`）里**暂停中的平台列表**，`[]` = 全部运行（第 7 个平台接入零改动）。模块级 `Set<CollectionPlatform>` 同步镜像供非 React 的 `startJob` 当 tick 判定，模块加载时 `getValue()` 填充 + `.watch()` 订阅跨 context 变更（形态同 `lib/i18n/index.ts` 的 `currentMessages`）。导出 `isLibraryPaused(jobPlatform)` / `gatePlatformOf(jobPlatform)` / `pauseLibrary` / `resumeLibrary` / `useLibraryGate(platform)`；正反 namespace 翻译委托给无副作用的 `collection-job-platform.ts`。`pause/resumeLibrary` 先改镜像（同 tick 生效，防点击与派发竞态）→ 再写 storage（watch 回声因值相同被吞）。**运行中 run 的 `pauseJob`/`resumeJob` 联动（5 个 kind fan-out）在 `applyPaused` 内按新旧集合 diff 驱动**——点击路径与跨 context watch（另一个 app.html tab 的写入）共用同一处联动逻辑；pause/resume 相位守卫使无 run 时（如模块加载的初始读）为幂等 no-op。**模块加载时 `setJobGate(isLibraryPaused)` 自注册**，app.html 的加载保证来自 `use-daily-auto-sync` 的 import（它由 `App.tsx` 挂载）。
- `use-jobs-badge.ts` — 工具栏 badge 同步 hook（挂 DashboardLayout，泛型层；单测 `use-jobs-badge.test.ts`）：`useRunningJobs().length` → `browser.action.setBadgeText`（数字，0 清空）+ `setTitle`（复用 `backgroundJobs.reminder` 文案当悬停提示，locale 切换随 re-render 更新）+ warning 橙底色。**只写不清理**：badge 文本是浏览器会话级持久，关掉 app.html 后由 SW 清道夫兜底擦除（`lib/background/jobs-badge.ts`），页面侧不做 unload 清理（unload 不可靠）。action API 失败一律吞掉只 warn（badge 属锦上添花，不能拖垮页面）。
- `use-daily-auto-sync.ts` — 每日首开自动同步协调器 hook（挂 `App.tsx`，跨路由常驻，单测 `use-daily-auto-sync.test.tsx`）。**触发 = mount + `visibilitychange`(visible)**（天然覆盖「登录后切回 tab 补拉」）；**节流 `EVALUATE_THROTTLE_MS=30_000`**（ref 记 `lastEvalAt`，用注入的 `deps.now()` 以便测试，防频繁切 tab 的 DB 查询风暴）。evaluate 每平台 `Promise.all` 并行 + try/catch 隔离（单平台失败/probe 抛错只 `console.error`，不阻断其它）：`shouldAutoSync` 未命中或 `probeReady` false → 跳过；否则 `deps.startJob(jobPlatform,'sync', runner)` 派发（跨路由存活 + 并发去重 + indicator 可见），runner 内 `runSync` 成功后 `startCollectionProcessingJobs`（空 `itemIds` 不触发），`isSilentError` 命中的错不 rethrow。`deps` 可注入（`initDb`/`now`/`getLastSynced`/`isPaused`/`startJob`/`startProcessing`）。**闸门插桩在 `shouldAutoSync` 之后、`probeReady` 之前**（`deps.isPaused(jobPlatform)`，默认 `isLibraryPaused`）：暂停中不发探针请求、不刷 `sources.lastFetchedAt`，解除暂停后当天仍会补跑；这只是省掉噪音 job，真正的兜底是 `startJob` 的 born-paused。**StrictMode double-invoke 由闸门 + startJob 去重 + 节流天然幂等**。

## 约定

- **config 函数必须引用稳定**（模块级常量或 useCallback）——它们在 effect 依赖数组里，不稳定引用会每 render 重查。
- **泛型层零 storage / 零平台导入**：唯一依赖 `@/lib/database` 的 `initDbProxy`。auth 解析（如 X 的 `getXAuth()`）必须留在各平台 adapter 的 `syncFn` 闭包内。**这条约束的是模块不是目录**：本目录分两档——泛型层（`background-jobs-store` / `pipeline-run-control` / `collection-processing-jobs` / `use-collection-library` / `collection-phase` / `daily-sync-gate` / `pipeline-segments` / `use-processing-coverage`）与平台感知层（`auto-sync-registry` / `library-gate` / `use-daily-auto-sync`，读 storage + 认识平台词汇是合法的）。跨档只能**由平台感知层向泛型层注入**（`setJobGate` / `deps`），泛型层反向 import 即视为掉档。
- 消费方（薄 adapter）：`sections/github-stars/use-github-stars.ts`（useSettings token 门 + estimatedTotal 进度计算）、`sections/x/use-x-bookmarks.ts`、`sections/zhihu/use-zhihu-favorites.ts`、`sections/youtube/use-youtube-playlists.ts`（useSettings 凭据门（github 模式）：apiKey+channel 同步读 `hasConfig`，无异步授权探针——API key 形态单维度）。**不适用**：bookmarks（auto-on-mount 同步）、bilibili（folders+videos 双 hook）——形态不同，不强行塞进该抽象（docs/15 HIGH-1 范围圈定）。
