# sections/douyin

抖音收藏页（`/collections/douyin`，第 7 个平台，docs/33 Step 2；**无 `:id` 详情路由**——公开收藏夹经 chips 单维筛选）。结构对齐知乎页（`sections/zhihu/`）：28px route h1 + 计数 · 「按作品发布时间排序」 · lastSynced + 获取按钮 → pipeline 行（strip + 闸门）→ 搜索框 → 配置提醒横幅 → 公开收藏夹 chips → 卡片 grid + Pagination。**数据一律从 PGlite 经 `lib/douyin/douyin-sync-service` 查询读取（UI 零 drizzle 导入）**；同步在 app.html 里编排，但每个请求都经 `lib/douyin/douyin-tab.ts` 注入到**用户自己已打开、已登录的 www.douyin.com 标签页**里发，由页面 SDK 签名（docs/33 D3 / D4）。favbase 从不自己开、刷新、导航或激活抖音标签页。凭据无 UI 半：没有 Connections 卡。

**面包屑**：`useCollectionBreadcrumbs('douyin')` → `首页 / 收藏夹 / 抖音收藏`。

## 模块结构

- `douyin-sync-adapter.ts` — 共享 Sync Adapter：`runDouyinSync(onProgress, control)` 单点定义「抖音同步成功意味着什么」。顺序：进度种子 → **`findDouyinTab()` 为 null 就在 funnel 之前抛 `DouyinAuthError('missing')`**（F1：没有可用标签页时平台根本问不到，这不需要联网就能知道，所以不算尝试、不写 Platform Sync Record，docs/32 §5.2；页面的未登录态认同一个错误类）→ `runPlatformSync('douyin', control, …)` 内读 `douyinBackfillStorage`（`local:douyin-backfill`）→ `syncDouyinCollections(douyinTabTransport, { backfill, onBackfill: setValue 写回, onPagePersisted, onProgress, control })` → 回报 `{ fetched, inserted, newItemIds: [] }`。**处理 lane 逐条派发（docs/33 D-b）**：每页入库后 `onPagePersisted(platformItemIds)` 对每条调 `enqueueCollectionProcessingItem({ jobPlatform, itemPlatform: 'douyin', itemId })`——`itemId` 是 **platformItemId（aweme_id）**，不是 `items.id`；首次全量约 20 分钟，第 80 页失败的运行不能留下 79 页「已切块、永不派发」的条目，而 funnel 只在成功时派发，所以 funnel 收 `[]`（它成功时的 embed 积压补跑照常）。写法与 `sections/bookmarks/use-bookmark-extraction.ts`、`sections/bilibili/bilibili-processing-adapter.ts` 同形（三处各自手拼三元组，没有命名的逐条派发入口）。标签页开着但没登录（F7）只有请求才知道，在 funnel 里，**算一次尝试**。另导出 `douyinAutoSyncPolicy`：`probeReady` = `findDouyinTab() !== null`（与前门、transport 同一个解析器，D-c——被丢弃 / 加载中的标签页不会烧掉当天名额），`isSilentError` = `err instanceof DouyinAuthError`（自动同步遇到未登录静默完成，记录照样是 `'failure'`）。手动页 `syncFn` 与 daily registry（`collection-platform-auto-sync.ts`，评估顺序最后一位）引用**同一函数**。契约测试 `douyin-sync-adapter.test.ts`
- `use-douyin-favorites.ts` — 数据 hook：共享 `useCollectionLibrary` 的薄 adapter，一句 `return useCollectionLibrary(config)`：模块级 `queryFn = facetQuery(getDouyinItems, 'folderId')`、`facetsFn = getFolderCounts`、`platform = PLATFORM`（`const PLATFORM = 'douyin'`）、`syncFn = runDouyinSync`、`jobPlatform = jobPlatformForCollection(PLATFORM)`——**值就是 `'douyin'`**（用户 2026-10-03 决定：bilibili / bookmarks 已是同名先例，不再给平台 id 发明第二个名字，所以不用 `'douyin-collections'`；其他四个平台的统一不在本步）。同步只由按钮触发，绝不 auto-on-mount
- `douyin-view.tsx` — scaffold Adapter，照 zhihu / x 装配：pipeline = Fetch → Embedding/Tagging（无 content 段，正文 `desc` 同步时即得）；`copy` 只传平台文案，caption = `douyin.count` · `douyin.sortedByPublishTime`（抖音不给逐条收藏时间，如实说明排序）· `common.lastSynced`。**两个可选 slot 都显式传**（`pipeline` 在 auth 相位传 `undefined`，同 zhihu；`configurationNotice` 恒传——漏传 `tsc` 不报，Tags 积压会失去恢复入口）。状态组件来自 `components/collection-states/`：库空 = `EmptyLibraryState` **带** `site`（打开抖音在前、获取 soft——库只能经已打开的抖音标签页填满，同 X）；auth 相位 = `NotLoggedInState`（`site` = 模块级 `DOUYIN_SITE`：`https://www.douyin.com/` + `douyin.openDouyin` + `simple-icons:tiktok`），文案说清「登录后保持这个标签页打开、回来点获取、首次全量约 20 分钟」。**错误文案是两条，不是一条**（用户 2026-10-03 决定：验证与冷却是两件事，`SyncErrorCopy` 本来就按 `resetAt` 的有无来选文案；docs/33 改法 5 原写的「验证码与限流共用」作废）：模块级 `SYNC_ERROR_COPY = { auth: 'douyin.notLoggedInTitle', rateLimited: 'douyin.verificationRequired', rateLimitedUntil: 'douyin.rateLimited' }`——共享 `syncErrorMessage` 按 `resetAt` 有无选键：`resetAt === null`（F6 验证页 / 挑战页）→「去抖音标签页完成验证后再试」；`resetAt` 非空（F4 / F5 / F8，favbase 自定的 30 分钟冷却）→「请求过于频繁，请于 {{reset}} 后再试」，并由 `useCountdown((now) => rateLimitRemainingMs(syncError, now))` 把标题栏「立即获取」锁成 `pipeline.fetchAvailableIn` 倒计时（照 x / github；锁只在内存、刷新即解，只锁标题栏按钮，错误相位的 Retry 与每日自动同步不看它——已知限制，未做）。公开收藏夹 chips = 共享 `FacetChips`（`simple-icons:tiktok` + `douyin.foldersTitle`，`getKey` = `folderId`、`getName` = `title`，名字空回退 id）；只有 `status === 1` 的公开夹是 Source，全部收藏里不在任何公开夹的条目只出现在「全部」下（docs/33 D1 / D-a）
- `douyin-card.tsx` — `CollectionCard` 装配：`media` 16:9 封面（`coverUrl` 原样，破图走外壳的 tiktok 字形回退；视频带 `CoverBadge` 时长角标，`durationMs` 四舍五入到秒）+ `header` 作者头像 24px + 昵称 + `title`（`desc` 首个非空行，3 行 clamp）+ `date`（发布时间）+ 图文作品（`mediaKind: 'note'`）的 `stamp` = `Label variant="soft"`（`douyin.mediaKind.note`）+ `tags`。`href` = `originalUrl`（视频 `/video/<id>`、图文 `/note/<id>`）。**封面跨域加载照先例**：外壳不设 `referrerPolicy`，加载失败回退字形；抖音 CDN 封面 URL 可能带会过期的签名参数——`[UNKNOWN]`，Step 3 实机验证，不在这里加机制
- `tagged-douyin-card.tsx` — 一行 `TaggedDouyinCard = taggedCard(DouyinCard, 'favorite', toDouyinItem)`，mapper 是 lib 分页查询导出的 `toDouyinItem`；TaggedItemGrid `renderCard` 与 `/collections` `CARD_ADAPTERS` 共用
- `douyin-grid-skeleton.tsx` — 共享 `CardGridSkeleton` + `CollectionCardSkeleton media="16/9" header lines={2}`
- `douyin-view.test.tsx` — 平铺平台 view 的第一份测试（此前五个平铺 view 都没有；形状照 `sections/configuration-heading.test.tsx`）：数据 hook 打桩、scaffold 换成记录 props 并渲染 slot 的探针、状态组件与 chips 真渲染。锁：无可用标签页的 auth 态（打开抖音链接 + 获取、无 pipeline 行、横幅照传）、库空态带打开抖音、两个可选 slot 都传、冷却锁按钮与倒计时文案、验证页不锁按钮且用验证文案、chips 计数

## 约定

- 页面顺序由共享 scaffold 固定；本目录只提供 adapter
- 排序固定 `publishedAt` 降序（作品发布时间；抖音无逐条收藏时间，同知乎妥协），caption 如实写出
- AI 后处理逐页派发（见上），共享 `douyin:embed|tag` 串行 lanes；Fetch worker 接收同一个 cooperative checkpoint，暂停落在「领取下一页」边界
- i18n：平台文案 `douyin.*`（zh/en 齐全，`douyin.count` 带 `.one`），导航名 `nav.douyinFavorites`（**不是** docs/33 写的 `nav.douyinCollections`：`Collection` 是 favbase 自己的领域词，见根 `CONTEXT.md`；抖音中文 UI 的「收藏」对应 TikTok 英文 UI 的「Favorites」，与 API 里 `favorite*` = 喜欢的陷阱无关），welcome hint `welcome.picker.hint.douyin`；同文案走 `common.*` / `pipeline.*`；无硬编码 CJK，视图里也没有英文硬编码文案
- 抖音 API 词汇陷阱只关乎端点：`collect*` = 收藏（本平台），`favorite*` = 喜欢 / 点赞（与本平台无关）
