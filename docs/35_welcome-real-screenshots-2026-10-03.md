## §2 哪些页面不能公开

采集时把 `app.html` 的十二个页面全截了（原图在主仓库
`docs/ui-baseline/2026-10-03/app-1440x900@2x/`，**未跟踪，不要提交**：里面有下面这些不能公开的页）。

| 页面 | 结论 | 原因 |
|---|---|---|
| 仪表盘 `#/` | 用 | 默认选中的 B 站明细会列出收藏夹名，其中有不适合公开的；改选 GitHub Stars 后只剩编程语言和仓库 owner（D7） |
| 全部收藏 `#/collections` | 用 | 首屏是公开推文 |
| GitHub Stars | 用 | 公开仓库 |
| X 书签 | 用 | 公开推文与作者 |
| 数据导出、通用设置 | 可用，未采用 | 没有敏感字段，但作为宣传图信息量低 |
| Chat | 不用 | 该浏览器未配置 LLM，页面是空态 |
| B 站、知乎 | 不用 | 收藏夹名是个人化措辞，会随扩展公开发布 |
| YouTube | 不用 | 首屏视频封面含不适合随产品发布的内容 |
| 浏览器书签 | 不用 | 文件夹名暴露学校、个人站点、本机地址 |
| 抖音 | 不用 | 另一个会话的未完成页面，空态 |
| 设置 > AI 配置、设置 > 账号连接 | **没有截** | 前者填着自定义 endpoint，后者有 token 字段 |

**公开前的检查不能省**：缩略图看不出收藏夹名。这次第一轮只看了缩略拼图，仪表盘四个变体里
有三个露出了不该公开的收藏夹名，是放大核对时才发现的。

## §3 采集方法

脚本：`docs/ui-baseline/capture-app-routes.mjs`（用法在文件头）。

1. **走 CDP，不走 BrowserOS MCP**。MCP（server 0.0.66 实测）能把 `chrome-extension://` 标签页
   开出来，但开完就不认它：`screenshot` / `run` 一律 `Unknown page`，`pages.list()` 不含任何
   扩展页。同一个浏览器的调试端口（9110）一切正常。
2. **只驱动自己开的标签页**，截完就关。`app.html` 没有跨标签页的任务锁：第二个标签页会把
   处理流水线（转录 / 正文提取）再跑一遍，对平台的请求频率翻倍。
3. **主题和语言的切换不能写共享存储**。配色存在 `localStorage`（会在其他扩展页触发
   `storage` 事件），语言存在 `chrome.storage`（所有 context 都 watch）。两者都是先改内存再
   持久化，所以脚本的 `isolate` 在本标签页里吞掉这两次写入，切换就只在这一个标签页生效，
   用的仍是产品自己的按钮。
4. **就绪判据**：`<main>` 里有 `h1`（路由的 Suspense fallback 没有）、没有 skeleton、所有
   `<img>` 已解码。不能拿 `role="progressbar"` 判断，流水线进度条本身就是内容。
5. 视口 1440×900、`deviceScaleFactor: 2`，出 2880×1800 的 PNG；发布用图缩到 2400×1500、
   WebP `quality=80, method=6`（Pillow）。画廊里最大显示宽度是 1280 CSS px，2400 约等于 2x。
6. Git Bash 会把参数里的 `#/collections` 改写成 Windows 路径，所以路由参数不带 `#/`，由脚本
   自己拼。

## §4 当前这批图的已知缺陷

都是截图当时那个库的真实状态，重截时消掉：

- 没配 LLM / Embedding：GitHub 和 X 页顶着黄色「需要完成配置」条，仪表盘「已用标签」是 0、
  覆盖率 0%，也因此没有 Chat 截图，而 Chat 是主功能。
- 「在用平台」显示 `6 / 7`：页面来自抖音 Step 2 的未完成构建，抖音还没有数据。
- 部分图的顶栏有「1 项后台任务未完成」的提示条：截图时处理流水线在跑。
- 「全部收藏」的条目数在四个变体里不一样（8,729 到 9,151），和仪表盘的 9,151 也对不上：
  采集期间 B 站同步在跑。仪表盘四张是后来连拍的，彼此一致。
- 中文界面的侧栏里「Analytics」没有翻译，是产品现状，不是截图问题。

## §5 重截清单

1. 配好 LLM 与 Embedding，等标签和向量跑完；在 Chat 里问一个有来源卡片的问题。
2. 等所有平台同步结束，顶栏没有后台任务提示。
3. 抖音落地并同步后再截，平台数才是终态。
4. 决定 B 站 / 知乎页要不要进画廊；要进就先处理收藏夹名（§2）。
5. 按 §3 采集，文件名不变（`tour-<page>-<scheme>-<locale>.webp`），原位覆盖
   `public/assets/images/welcome/`。加页面或减页面要同时改三处：
   `entrypoints/welcome/tour-images.ts` 的页面清单（`tour-images.test.ts` 会和目录双向对账）、
   `sections/product-tour.tsx` 的 `ITEM_COPY`（它按页面 id 穷举，漏了 `tsc` 会报）、两个 locale
   的 `welcome.tour.<page>.desc`。
6. 逐张放大核对内容后再提交（§2 末段）。

## §6 采集时发现、与本任务无关的两件事

- **已加载的扩展目录被重新构建后，已打开的标签页会坏**：入口 chunk 是旧的，还没加载过的
  路由去取的 chunk 已被新构建删掉，报 `Failed to fetch dynamically imported module`。刷新
  该标签页即可。
- **`app.html` 多开会重复跑后台任务**（§3 第 2 条）。这是产品现状，用户自己开两个标签页也
  会触发。

## §7 实测与三处偏离（D8）

worktree 的构建装不进浏览器（已加载的是主仓库的 `.output`），所以用本地静态服务器托管
`.output/chrome-mv3`，经 CDP 的 `Page.addScriptToEvaluateOnNewDocument` 注入一个最小的
`chrome` / `browser` 桩（`runtime.id`、`getManifest`、`storage.*`），让真实打包出来的
`welcome.html` 在 `http://127.0.0.1` 上跑起来，再滚动、截图、读 `getBoundingClientRect`。
它验证的是打包产物的布局与资源路径，不验证扩展 API 行为。

照搬源文件的第一版量出三个问题，改完后同一组指标复测：

| 指标 | 视口 | 改前 | 改后 |
|---|---|---|---|
| 粘住时条目标题的顶边（顶栏底边 72） | 1440×900 | 37，被顶栏盖住 | 96 |
| 粘住时截图的底边 | 1440×900 | 863 | 876（视口 900） |
| 同上 | 1440×640 | 未测 | 616（视口 640） |
| 条目图标中心相对标题中心 | 全部 | 低 11px | 0 |
| 条目文字块宽度（截图宽 480） | 390×800 | 602 | 436，说明折两行 |

对应的三处偏离（算术在 `entrypoints/welcome/CLAUDE.md` 的 `product-tour.tsx` 条目）：

1. 粘住区从顶栏下方开始，截图宽度按剩余高度封顶，上下各留 24px。1440×900 下截图是
   1066×666；视口高度到 947px 才是源文件的 1140×713。Minimal 自己的截图也是 16:10，矮视口下
   同样会被顶栏盖住，这里不跟。
2. 图标的纵向偏移从主题的 `h3` 行高算出来。源文件的 `10px` 是按 Minimal 的 `h3`
   （32px × 1.5）调的，本仓库的 `h3` 是 20px × 1.3。
3. 宽度表放在条目根上，文字块不再比截图宽。

在 1440×900、1440×640、960×800、390×800 四档以及亮 / 暗、中 / 英、减弱动效下看过：16 张图
都按配色和语言取到对应文件，页面无横向溢出，控制台零报错。**没有在已安装的扩展里看过**，
合并后在真实的 `welcome.html` 里再过一遍。
